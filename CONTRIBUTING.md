# Разработка

Команды выполняются из корня репозитория. Нужны Go 1.26, Make и Docker с Compose
для интеграционных проверок.

```sh
make deps
make tools
make check
```

`make check` проверяет форматирование, актуальность OpenAPI, линтер, race-тесты
и сборку. Зависимости и версия линтера закреплены в проекте.

## Изменения

Один pull request должен решать одну задачу. Опишите, какое поведение меняется
и как вы его проверили. Для исправления ошибки добавьте тест, который её воспроизводит.

Соблюдайте текущие границы: HTTP-контроллер разбирает запрос, сервис выполняет
сценарий, runtime владеет состоянием, storage обращается к SDK. При изменении
HTTP-контракта обновите его описание в маршрутах и выполните:

```sh
make docs
make check
```

Изменение контракта или настройки должно быть отражено в [README](README.md)
и `.env.example`, если добавлена переменная окружения. Сгенерированный
`swagger.generated.json` сохраняется в Git вместе с исходным контрактом.

## Проверки с MinIO

Интеграции изменяют данные. Запускайте их только на одноразовых fixtures проекта;
не подставляйте адрес рабочего хранилища или его ключи.

```sh
(
  set -eu
  trap 'make fixtures-down' EXIT
  make fixtures-up
  make test-integration
)
```

Fixtures занимают порты `19000`, `19001`, `19002` и используют tmpfs.
Вывод пула из эксплуатации проверяется отдельно: после него fixture пула
нужно пересоздать перед остальными тестами топологии. Подробности — в [README](README.md).

Не добавляйте в коммиты локальные env, credentials, cookie, подписанные URL,
бинарники, `.tools` и результаты тестов.
